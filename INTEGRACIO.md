# Integrálás a meglévő Spring Boot + Angular projektbe

Becsült idő: 1–2 óra, plusz a külső rendszerekben a tokenek és jogosultságok beállítása.

**Előfeltételek:**
- Spring Boot 3.2+ (a `RestClient` miatt) és Java 17+.
- Angular 17+ (a `@if` / `@for` szintaxis és a `styleUrl` miatt).
- Spring Boot 2 (javax) alatt a kód nem működik, ott a `jakarta.*` importokat vissza kell írni, a `RestClient`-et pedig `RestTemplate`-re kell cserélni.

---

## 1. Backend

### 1.1 Kód átmásolása

Másold a `backend/src/main/java/com/example/projectkickoff` mappát a projektbe. Utána nevezd át a csomagot az IDE-ben (Refactor → Rename package), pl. `hu.ceg.syncro.kickoff` névre.

**Fontos:** a csomag a `@SpringBootApplication` osztály csomagja **alá** kerüljön. Így a component scan, az entitások és a repository automatikusan betöltődnek. Ha a projektben van explicit `@EntityScan` vagy `@EnableJpaRepositories`, azokba vedd fel az új csomagot is.

### 1.2 Függőségek (pom.xml)

A web, a data-jpa és a validation starter valószínűleg már megvan. Ha nem, vedd fel őket. A Drive-hoz ez is kell:

```xml
<dependency>
    <groupId>com.google.auth</groupId>
    <artifactId>google-auth-library-oauth2-http</artifactId>
    <version>1.29.0</version>
</dependency>
```

### 1.3 Adatbázis

A `backend/sql/V1__project_kickoff.postgresql.sql` fájl 3 táblát hoz létre (`project_kickoff`, `project_kickoff_member`, `project_kickoff_step`).
- **Flyway:** nevezd át a következő sorszámra (pl. `V42__project_kickoff.sql`), és tedd a `db/migration` alá.
- **Liquibase:** vedd fel `sqlFile` changesetként.
- Nem PostgreSQL esetén a `GENERATED BY DEFAULT AS IDENTITY` és a `TIMESTAMP WITH TIME ZONE` típusokat igazítsd az adatbázishoz.

### 1.4 Konfiguráció

Másold a `backend/src/main/resources/application-kickoff.example.yml` tartalmát az `application.yml`-be, és töltsd ki. A tokenek környezeti változókból jöjjenek. Egyenként is bekapcsolhatod az integrációkat, érdemes egyesével haladni.

### 1.5 Syncro bekötése

Mivel a modul magába a Syncro-ba kerül, nem kell REST-en hívni. Hagyd üresen a `kickoff.syncro.base-url` értéket, és implementáld a `SyncroGateway` interfészt a meglévő projekt service-szel:

```java
@Component
@RequiredArgsConstructor
public class InternalSyncroGateway implements SyncroGateway {

    private final ProjectService projectService;   // a Syncro saját service-e
    private final UserService userService;

    @Override
    @Transactional
    public SyncroProjectRef upsertProject(SyncroProjectCommand cmd) {
        // Idempotens legyen: ugyanarra a kulcsra ne hozzon létre új projektet, hanem frissítse.
        Project p = projectService.findByKey(cmd.projectKey())
                .orElseGet(() -> projectService.create(cmd.projectKey(), cmd.name()));
        p.setDescription(cmd.description());
        p.setProjectManager(userService.getByEmail(cmd.projectManagerEmail()));
        cmd.members().forEach(m -> p.addMember(userService.getByEmail(m.email()), m.role()));
        p.setGitlabUrl(cmd.links().get(StepType.GITLAB));
        p.setMattermostUrl(cmd.links().get(StepType.MATTERMOST));
        p.setDriveUrl(cmd.links().get(StepType.DRIVE));
        p.setWikiUrl(cmd.links().get(StepType.BOOKSTACK));
        projectService.save(p);
        return new SyncroProjectRef(p.getId().toString(), "/projects/" + p.getId());
    }
}
```

Ezután állítsd be: `kickoff.syncro.enabled: true`.

### 1.6 Személykereső (ajánlott)

Alapból a Mattermost felhasználói között keres. Ha a Syncro-ban megvannak a munkatársak, jobb azokból keresni:

```java
@Component
@RequiredArgsConstructor
public class SyncroPersonDirectory implements PersonDirectory {
    private final UserRepository users;

    @Override
    public List<Person> search(String query, int limit) {
        return users.searchActive(query, PageRequest.of(0, limit)).stream()
                .map(u -> new Person(u.getEmail(), u.getFullName()))
                .toList();
    }
}
```

### 1.7 Jogosultság

Az endpoint a `/api/project-kickoffs/**` útvonalon van. A meglévő security configban kösd projektvezetői szerepkörhöz:

```java
.requestMatchers("/api/project-kickoffs/**").hasRole("PROJECT_MANAGER")
```

A `createdBy` mezőbe automatikusan a bejelentkezett felhasználó neve kerül.

### 1.8 Ellenőrzés

Indítsd el az appot, majd hívd meg:

```bash
curl http://localhost:8080/api/project-kickoffs/options
```

A válaszban a bekapcsolt integrációk listája jön.

## 2. Frontend

1. Másold a `frontend/project-kickoff/` mappát a `src/app/` alá.
2. Vedd fel a routingba:
   ```ts
   {
     path: 'projektinditas',
     loadChildren: () => import('./project-kickoff/project-kickoff.routes').then(m => m.PROJECT_KICKOFF_ROUTES),
     // canActivate: [pmGuard],   // ha van szerepkör guard
   }
   ```
3. Legyen `provideHttpClient()` (standalone app) vagy `HttpClientModule` (NgModule app). Valószínűleg már megvan.
4. Ha a backend nem a `/api` prefixen érhető el, add meg:
   ```ts
   { provide: KICKOFF_API_URL, useValue: `${environment.apiUrl}/project-kickoffs` }
   ```
5. A stílus keretrendszer-független, a színek CSS változókkal igazíthatók a témához (`--kickoff-primary` stb.). Ha Angular Materialt használtok, a HTML-ben a mezők könnyen `mat-form-field`-re cserélhetők.
6. A közös `project-kickoff.scss` kb. 3,3 kB. Az Angular alap `anyComponentStyle` limitje 2 kB, ezért build közben figyelmeztetés jöhet. Ilyenkor emeld meg a limitet az `angular.json`-ban 4 kB-ra, vagy tedd a scss-t a globális stílusok közé.
7. Menüpont: `routerLink="/projektinditas"`.

## 3. Beállítások a külső rendszerekben

| Rendszer | Mit kell létrehozni | Jogosultság |
|---|---|---|
| **GitLab** | Personal Access Token (vagy group access token a szülőcsoporton), `api` scope | Owner a szülőcsoporton. **Admin token ajánlott:** csak azzal működik megbízhatóan az e-mail alapú felhasználókeresés, ha a felhasználóknak nincs publikus e-mail címük. |
| **Mattermost** | Bot account + token (System Console → Integrations → Bot Accounts), felvéve a csapatba | Csatorna létrehozása (nyilvános és privát), csatornatagok kezelése, csapatba felvétel. A legegyszerűbb, ha a bot „System Admin” szerepkört kap. |
| **Google Drive** | Google Cloud projektben service account + JSON kulcs, bekapcsolt Drive API | A service account legyen **Content manager** a projekteket tároló Shared Drive-on. Vagy domain-wide delegationnel (`impersonate-user`) egy felhasználó nevében dolgozik. |
| **BookStack** (v23.05+) | API token egy technikai felhasználónál (Profil → API Tokens) | Hozzáférés a rendszer API-hoz, könyvek létrehozása, szerepkörök, felhasználók és jogosultságok kezelése. A legegyszerűbb az Admin szerepkör. |

## 4. Döntések, amiket érdemes ellenőrizni

Ezeket feltételezésként építettem be; mind konfigurálható, vagy kis módosítással átírható:

1. **Drive = Google Drive.** Ha SharePoint/OneDrive-ot használtok, a `DriveStepHandler` helyett egy Microsoft Graph-os implementáció kell. A `StepHandler` interfész miatt ez egyetlen új osztály.
2. **GitLab:** a projekt egy saját **csoportot** kap (a konfigurált szülőcsoport alatt), benne egy azonos nevű repóval. A tagok csoport szinten kerülnek be. Ha nem kell repo, állítsd be: `create-project: false`.
3. **BookStack:** projektenként egy **könyv** jön létre, benne egy nyitóoldallal. Alapból mindenki látja, a tagok szerkeszthetik. Ha csak a tagok láthatják, állítsd be: `restrict-to-members: true`.
4. **Szerepkörök:** projektvezető, tag és megtekintő (csak olvasás). A GitLab szintek konfigurálhatók.
5. **Mattermost:** alapból privát csatorna, ez az űrlapon átállítható.
